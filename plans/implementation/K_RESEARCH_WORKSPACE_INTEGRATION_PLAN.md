# Research workspace implementation and integration plan

Planning baseline: 2026-10-14. This is a detailed implementation overlay on [the complete repair plan](J_REPAIR_UNBLOCK_COMPLETION_PLAN.md), not a replacement for its original requirements, dependencies or release gates. No package below is accepted. Production implementation and deployment have not occurred in this planning step.

## Outcome and current gap

The acceptance workflow is a normal browser session: upload a PDF, observe bounded processing, inspect structured knowledge and candidate memories, ask a question in ordinary chat, receive an explanation with sources, open the cited PDF at the supported passage, switch subjects deliberately, compare documents, and repeat after restart. An isolated script, a healthy container or a vector similarity result does not establish this outcome.

The live deployment remains older than the staged candidate. Current UI chat uses lexical retrieval; semantic search is a separate interface requiring a client vector and explicit documents. Upload assembly does not commission an automatic durable encoder job. Citations identify chunks and pages without native rendered-text anchors. The canvas viewer lacks a positioned text layer. Opening a PDF currently changes subsequent question scope implicitly. These are implementation gaps, not merely missing evidence.

The existing 14-paper corpus is development data. Existing structural, custody and API checks remain useful but do not establish scientific extraction accuracy, held-out answer quality or exact visual highlighting.

## Researched design constraints

1. Use immutable quote/context anchors plus positions, rather than offsets alone. The [W3C annotation model](https://www.w3.org/TR/annotation-model/#text-quote-selector) provides exact quote, prefix/suffix and position concepts. Our normalization must retain a reversible map; Python code points and browser UTF-16 offsets differ.
2. Render and locate against the same hash-verified PDF revision. [PDF.js viewport examples](https://mozilla.github.io/pdf.js/examples/) describe scale, rotation and coordinate transforms. The locally pinned 6.4.299 implementation has point conversions; do not assume an older rectangle conversion API. Transform all four corners. Keep CSS coordinates distinct from device pixels.
3. Bundle the text-layer styles with their license and version/integrity provenance. The [exact pinned stylesheet](https://raw.githubusercontent.com/mozilla/pdf.js/v6.4.299/web/text_layer_builder.css) uses scale-related CSS variables. Latest API documentation alone is insufficient for this pinned bundle.
4. Keep the encoder CPU-only, bounded and reusable. [ONNX Runtime threading guidance](https://onnxruntime.ai/docs/performance/tune-performance/threading.html) explains thread and spinning costs. Benchmark existing explicit thread settings and worker idle lifetime before increasing concurrency or changing models.

Local compatibility evidence: [probe report](../../evidence/research-ui/pdfjs-spike.json), generated by [isolated probe](../../evidence/research-ui/pdfjs_spike.py). Twelve combinations of three scales and four rotations passed at device pixel ratio 2 under a restrictive local CSP, with owned temporary files removed. The initial probe used an unavailable document cleanup method; corrected to loading-task cleanup and recorded in the report. Font-data warnings remain. This checks compatibility and coordinate round trips on synthetic text, not glyph accuracy, quote disambiguation or the integrated UI.

Private references remain architectural research only. Existing reference inventory and REF cards govern what was actually reviewed. No claim is made that every reference implementation has been executed or that proprietary feature descriptions establish permission to copy code, fixtures, dictionaries or assets.

## Integration contracts

**Explicit question scope.** Each request carries a scope kind (`library`, `documents`, `page`), selected IDs as appropriate, and a scope generation. The server resolves authorized documents and revisions into a reproducible scope snapshot. Viewing a citation changes viewer state only. Explicit controls change chat scope; history and candidate memory are bound to that scope. Topic labels aid navigation and never grant authorization.

**Citation anchor.** Versioned fields include document ID, original SHA-256, revision, extraction generation, page, span/node/chunk IDs, extraction kind, exact quote, prefix/suffix, normalized offsets, normalization recipe and text digest. Optional PDF quadrilaterals require coordinate provenance. Status distinguishes `exact-native`, `ocr-region-unverified`, `ambiguous`, `page-only` and `unavailable`. Author-source TeX with no PDF alignment cannot masquerade as a page citation. Older clients retain existing citation fields; new fields are additive and versioned.

**Matching.** Match against bounded page text with reversible normalization for whitespace, ligatures and line-break hyphenation. Resolve unique quote plus context; repeated matches remain ambiguous unless additional valid evidence resolves them. Map normalized positions through original text to DOM ranges. Never choose the first match as an implicit fallback. Recheck source identity before drawing. Native extraction order and PDF.js item order may differ and require explicit matching tests.

**Semantic lifecycle.** Upload stages source custody, extraction, structured assembly, encoder queue, mapping and ready/partial/failed status. Durable jobs carry document revision, model digest, artifact generation, bounded attempt count and idempotency key. Publish a complete validated generation atomically; a stale job cannot activate after replacement or deletion. Append-only migrations preserve prior generations and rollback references. No parser model access, Docker socket, global control credential or unbounded retry loop.

**Ordinary Ask.** A server-side query encoder removes the client-vector prerequisite. The retrieval gateway combines independently evaluated lexical and semantic candidates, validates ACLs before use and again before returning sources, and records source/model generations. Start with bounded exact cosine search; add a larger index only if measured workload requires it. A library exceeding a per-call bound must use complete bounded traversal or explicit admission feedback, never silent first-N selection.

**Grounded explanation.** Claims map to supporting citations; comparisons identify both sources. Candidate memories and graph neighbors do not become factual authority. Distinguish supported text from unsupported figures, tables, formulas and absence claims. Diagnose prior citation/schema failures on the actual application path before modifying model settings. Keep actual tokenizer admission and the existing live 4K context until measured quality and resource evidence supports a change.

**Concurrency and UI.** Bind asynchronous results to authentication, question scope, source revision, request and render generations. Discard stale results after logout, scope change or source replacement. Zoom, rotation and resize recompute the same anchor. Preserve cancellation and resource caps. Bundle required fonts locally with hashes/licenses, enforce CSP without external fetches, and test a missing-font case explicitly.

## Capacity decision and qualification protocol

The user-approved engineering target is **P1: 1,000 PDFs and 50,000 total pages**. These are paired capacity bounds, not demonstrated support. **P0: 100 PDFs and 5,000 pages** is the required independently verified first milestone. **P2: 10,000 PDFs and 500,000 pages** is a separate optional scalability exercise; it is not a release gate. Failure to reach P1 must be reported as an unmet release target, even if P0 passes.

Active upload limits remain **2 MiB and 100 pages**. Qualify **25 MiB and 250 pages** for standard uploads before enabling that envelope. **100 MiB and 1,000 pages** requires a separate large-file gate. Both byte and page checks apply. Limit expansion must cover proxy/body handling, streaming upload, parser output limits, OCR, temporary disk, artifacts, database writes and browser rendering, not merely an HTML input setting. Existing aggregate extraction-character limits must be assessed explicitly; truncated text cannot be called fully ingested.

Target ingestion concurrency is **two documents, configurable**, after resource admission and tests. Use a global bounded scheduler with per-actor fairness, bounded waiting queue, explicit queued/rejected responses, deadlines, cancellation and resource reservations. Preserve current live settings until tested. Reserve disk headroom for original files, temporary extraction, staged and prior generations, indexes, transaction logs and backup/restore. CPU, RAM, disk, page/OCR complexity, stage time and queue limits are checked before and during work; exhausted budgets isolate the job rather than crash the service.

Successful indexing is incremental. Retain immutable originals, content hashes and per-source generations. Retry durable stage checkpoints with bounded attempts and verified input/output hashes. A crash resumes or safely redoes a stage; it does not rebuild the library. Publish knowledge, embeddings, graph and search visibility as one validated generation. Failed jobs expose status but no partial searchable generation. Previously valid generations remain available during replacement until atomic activation succeeds.

Content-hash deduplication avoids redundant processing within an authorized ownership boundary. Shared physical artifacts, if supported, require independent ACL references, safe reference counting and deletion. Upload responses, timing and duplicate discovery must not reveal another actor's private document. Same bytes under different authorized metadata do not silently merge access rights.

Every successfully indexed authorized document must be eligible for library-wide search. Bound the evidence working set sent to inference, not the searchable library. Persist model/source generations and authorization filters in the retrieval path; recheck source access before citation delivery. Benchmark an incrementally maintained lexical index plus bounded vector storage/search against exact cosine and independent relevance labels. An approximate index, if justified, must have measured recall, deletion/replacement consistency and authorization-safe candidate filtering. Avoid loading all graph JSON or re-encoding all passages per query. A rebuild or model upgrade creates a separate validated generation while the previous index remains usable.

At each attempted tier record actual distinct PDFs, original page counts, fully indexed pages, OCR pages, extracted characters, passage/graph/vector counts and input bytes. Use a manifest with content hashes and legally usable fixtures. Separate native text, scanned, mixed-layout, formula-heavy and malformed cohorts; replicated synthetic documents can establish load behavior but cannot substitute for independent mixed-domain content or retrieval labels. Do not download thousands of random papers without a bounded corpus acquisition plan.

Measure stage and total documents/pages per minute, cold/warm p50/p95 ingestion and retrieval latency, peak whole-stack and per-service RAM, CPU time, queue wait and saturation, original/artifact/index/database disk growth, graph-validation time, and recovery time/lost or duplicated jobs. Distinguish throughput at concurrency one and two. Record hardware, exact images/models, limits and sample counts. Run retrieval concurrently with ingestion. Predeclare service latency/resource budgets before qualification; do not derive passing thresholds after seeing results.

Fault qualification covers worker/container restart, full database restart, mid-stage failure, duplicate submission, corrupt checkpoint, disk pressure, queue overload, unauthorized retrieval and source deletion/replacement. Verify no partially published source, no lost committed work, no duplicate active generation, and backup restoration into an isolated stack. P0 requires independent review of manifest counts, lineage, retrieval labels and restart receipts. P1 requires reliable incremental operation at full target scale, without treating P0 results as linear extrapolation. Publish measured supported envelopes and failures separately from proposed targets. No new capacity is enabled automatically by a benchmark receipt.

This capacity decision does not enlarge model context. Keep the existing context admission, small evidence-backed retrieval working set and CPU-first execution. AMD/Evolus and central security activation remain deferred.

## Testing and evidence — separate from deployment

- Create independent golden source spans and visual locations before tuning. Test correct page, quote, source hash and bounding geometry; prohibit false exact labels. OCR confidence is uncalibrated unless calibrated against independent labels. The two unsupported rotated development pages remain explicit failures until repaired and verified.
- Freeze held-out subject questions, answer-support labels, ambiguous/no-evidence cases and cross-document comparisons before tuning. The existing 14 papers may supply regression cases but cannot be the sole release holdout. A failed holdout followed by tuning requires a fresh holdout.
- Predeclare acceptance thresholds and measurement conditions per card before implementation. Security/custody must-deny cases and synthetic exact native anchors require 100% success. Domain answer-quality and service latency targets require workload-specific review; no invented throughput or accuracy threshold is treated as already approved.
- Exercise queue crashes, database unavailability, incomplete generations, hash corruption, unauthorized sources, source replacement, prompt injection, oversized PDFs, model timeouts, cancellation and stale UI responses. Check negative paths through ordinary UI as well as APIs.
- Store scoped results under `evidence/research-ui/` and later release-validation runs, with build/source/fixture hashes, commands, counts, duration, resource environment, failures and cleanup. Keep historical failures. Do not label planning coverage, static inventories or synthetic compatibility as product certification.
