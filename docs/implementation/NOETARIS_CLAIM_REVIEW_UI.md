# NOETARIS source-claim review UI

The live /app/knowledge/review placeholder now has a reviewer/admin interface backed by actual source-claim APIs. Demo mode retains the supplied placeholder tiles. Existing canonical read/review permissions and content admission remain required independently; uploading a document does not grant review authority. Individual-user HTTP admission remains closed. No source/schema or identity migration is introduced.

The list uses25-row authorized keyset pages, includes closed records and shows bounded active/historical conflict summaries. These are authorized-subset observations, not assertions about hidden documents or semantic completeness. Source inspection binds exact chosen claim/revision, original source hash, source submitter, immutable source-span citation and actor/role-specific comparison context. The chosen original's byte integrity does not certify the claim's truth or an AI answer. PDF links carry actual returned quote anchors into the existing SHA-bound workspace; other source evidence remains inspectable in the library.

Comparison pages expose every current authorized active alternative up to the backend's explicit2000-alternative bound. Loaded coverage is tracked only within a matching context hash; changing context discards it. Acceptance is disabled until every alternative page is loaded and the reviewer acknowledges original-source inspection. Contest/reject affect the chosen projection and still bind the complete current context. All actions send exact expected_revision, expected_context and untruncated10-2000-character rationale. The backend independently enforces source visibility, source submitter independence, original integrity, comparison freshness and revision consistency.

The root tab store retains rationale drafts across ordinary source/PDF navigation, while new reads reestablish comparison coverage. It keeps captured requests separate from subsequent typing and applies read/view/identity epochs so delayed data cannot replace another claim. Successful decisions use exact server claim/revision/context/supersession/audit receipts and reload data instead of optimistic status edits. Rationale notes for closed claims remain inspectable and explicitly clearable. Browser reload or identity change clears tab state; credentials and transcripts are not persisted to browser storage.

Uncertain decision responses are never automatically retried. A fresh authorized target read reports only observed state/revision and explicitly does not attribute the original decision or invent an audit receipt. Up to10 unresolved local snapshots can be preserved while another review proceeds; resolved snapshots require explicit local clearing. Up to100 rationale drafts are retained without silent eviction. Full history/originals remain server-side, independent of local snapshot clearing.

Event history uses25-record pages with exact signed64-bit string IDs throughout requests, keys and rendering. Every page rechecks complete current authorization. Full event details, previous states, rationale and supersession lineage remain inspectable. This is a snapshot of the latest successful event read, separate from the comparison snapshot; it is not a global audit-chain attestation. Source and event text is rendered as data, never executed.

Evidence fixture evidence/noetaris-integration/verify_claim_review_stack.py ingests actual native PDFs and uses real local encoder publication. It creates30 source-backed alternatives, retains27 actual historical decisions, follows the returned source citation to unique PDF highlighting, checks all-page acceptance gating, adds a real new alternative to force stale-context409, accepts the fresh31-alternative group, verifies originals/closed rows persist, traverses29 exact event IDs above2^53, loses a real committed response and observes current state without replay/false attribution, delivers a real delayed comparison after switching claims, inspects the closed alternative without enabled actions, checks populated widths and verifies uploader/individual admission boundaries. All roles/sources are synthetic policy fixtures, not independent semantic or release acceptance.

A concurrent and a standalone one-CPU/two-thread CPU-generation regression failed during this integration; both receipts and model-cancellation logs are retained. An isolated two-CPU/two-thread, 4GiB/context4096 run passed all30 checks including actual source-bound generation in116.224 seconds. Docker CPU/memory limits were inspected, and API deadlines were unchanged. This bounded success cannot erase earlier failures or qualify contention/cold-start latency. The six-CPU/context8192 deployment profile remains separately unqualified. Resource/performance and five-user capacity qualification remain separate release requirements. No latency/certification percentage is inferred from the claim-review checks.

Exact source hashes, image identities, current and failed receipts are maintained in evidence/noetaris-integration/current-evidence.json and claim-review-ui-changed-files.json. The API is unchanged from its existing1364-test exact-image qualification and current-schema clone restore; final frontend verification is separately image-bound. Rollback uses the preceding frontend image in pre-claim-review-ui-current-evidence.json, retains the current fixed API/schema and preserves all subsequent claims/events/originals. No live service replacement or data rewind occurred.

The remaining semantic fabric, memory/promotion/retention, governed approvals, voice/provider/deployment work and independent security/rights/capacity/held-out acceptance gates remain in the full objective. Source-claim review states are reviewer decisions, not automated factual or release certification.
