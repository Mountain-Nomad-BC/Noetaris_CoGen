# NOETARIS session-bound memory inspection

The live /app/memory route replaces the memory placeholder with actual GET /v1/memory/{session_id} observations. Only admitted canonical identities with chat permission can mount it; the backend independently enforces permission, session ownership and current complete source authorization. Individual-user content admission remains unchanged. No schema, source, canonical claim or identity migration is introduced.

Own canonical conversations are listed through the existing owner-bound paginated history API. Selecting a conversation starts an explicit authorized-library inspection. The active-chat action copies that conversation and its current explicit scope after validation; it does not change the chat draft or question scope. Source/revision/page filters survive in the memory URL. Invalid scope, stale revisions and unavailable records fail closed rather than showing previous observations as current.

The view distinguishes bounded recent working context, reviewed claims, own reflection proposals, conflict alternatives/quarantine and explicitly scoped source-observation candidates. It shows byte bounds, projection receipt, query plan, complete dependency IDs or the backend manifest reference, omission counts and bounded selection limitations. Inspection has no question relevance query and is not presented as the exact prompt used by an earlier answer. Neither projection eligibility nor reviewed reflection state grants factual authority to generated explanations.

Working text is labelled as bounded context, potentially a stored preview; the retained-conversation link exposes full durable assistant receipts. Omission counts apply only within already bounded input windows and do not imply that older records were deleted. Source candidates retain omitted-character counts and link their exact graph-node IDs into the Atlas for complete source text and lineage. Atlas deep links now honor a validated node ID bound to the selected source artifact.

The browser validates session/actor, exact source scope, proposal-only writeback, quarantine policy, byte/record limits, complete dependency inventories and review/source metadata. Explicit source scope cannot silently include working conversation. Candidate observations cannot declare canonical authority. Requests and rendered state are keyed to exact scope and identity; unmount aborts reads and late replies cannot populate another screen. Distinct React keys prevent duplicate scope editors/projections during URL transitions. Browser reload intentionally clears local role credentials; credentials and transcripts are not persisted by this page.

The page is inspection-only. Creating/reviewing reflection proposals is now integrated separately at /app/learning (NOETARIS_REFLECTION_UI.md). The promotion ledger and broader retention controls remain separate work. Existing backend governance and review APIs are preserved. Demo mode retains the supplied placeholder tiles.
