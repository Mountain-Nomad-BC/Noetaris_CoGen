# NOETARIS attributed reflection and independent review UI

The live /app/learning route now supports operators creating source-attributed reflections and reviewer/admin identities inspecting and deciding currently authorized proposals. Existing private admission and backend permissions remain independent requirements. Reflection decisions never promote source claims, generated explanations, model weights or canonical knowledge. The memory page links to these governed workflows; demo placeholder screens remain preserved.

Operators choose an actual attributable claim from paginated authorized claim pages and explicitly bind it to a tab-memory draft. Literal reflection text, including whitespace, is validated without truncation. The request sends only source_claim_id and reflection; actor, authority, dependency collection and source access remain server responsibilities. A successful response preserves the current draft and captured submitted snapshot separately, including text typed during the request. Source inspection/navigation preserves the draft and its attribution. Identity changes/reloads clear browser draft state; no credentials or transcripts are stored in browser persistence.

Own and review lists use actual25-row keyset pages and state filters with totals/has_more. All167 own records in the navigation fixture remain reachable beyond the former100-row cap. Legacy incomplete provenance remains labelled and does not enable decisions. Records show source claim state, locator, original identity and a complete attributable JSON view. Inspecting original source/graph does not mutate authority.

Review actions require a current candidate, a different author, complete origin-source provenance, exact revision and10-2000-character rationale. The backend preserves compatibility for older clients that omit rationale, while this UI requires it. The audited transition now retains rationale, source_claim_id, old/new state and revision. Responses bind exact proposal ID, new revision, decision, nonauthority and audit receipt. The UI clears decision rows while a mutation is pending or uncertain and reloads server state instead of applying optimistic status changes. A stale/closed decision is rejected; current rows must be reloaded before another decision.

A lost submission response is not automatically retried. Reloading own pages reconciles an exact retained source-claim/text match; older pages and All filter remain accessible. A lost review response reconciles only observed current row state/revision and explicitly does not attribute the original decision or invent an audit receipt. Users may preserve a bounded unresolved request snapshot and continue their current draft; up to10 such snapshots remain inspectable without eviction. Reconciled local snapshots require explicit clearing. Review notes, including notes for closed records, have an explicit retained-draft panel and clear action; at most100 open note drafts are retained without silent eviction. Dictionary-safe storage preserves legacy record identifiers without prototype-name collisions.

Root identity epochs cancel/ignore late replies after identity changes. Submission/review requests continue in root tab state across ordinary source navigation, preserving the actual captured request. Browser reads are keyed to actor, view, filter, cursor and reload; current source/row authorization is rechecked by the backend. Self-review, forged source provenance and stale revisions are independently rejected on the server.
