# Source-claim comparison and history foundation

The claim-review UI needs source-bound comparison and event APIs before replacing its placeholder. This increment supplies that foundation and repairs concurrent supersession; the live claim-review screen is still pending.

GET /v1/claims/{claim_id}?offset=0 requires the existing admitted canonical read identity. It returns the exact chosen claim, original source-span citation, chosen-source SHA-256 verification, source submitter, currently authorized active alternatives,25-row pagination, total/next offset and an actor/role-bound context_sha256. The context hashes the full authorized subject/predicate comparison group, not only the displayed page. It is a concurrency fingerprint, never an authorization token or factual-correctness proof. Only reviewer/admin roles distinct from the source submitter receive can_review=true, and every mutation independently rechecks authority. Private admins retain the existing explicit-grant and committed privileged-read audit requirements through database authorization.

The comparison bound is2000 active alternatives. Exceeding it fails explicitly; no partial group is approved or silently truncated. Original source custody remains preserved. Comparison scope follows the current backend subject/predicate grouping; semantic equivalence, conditions and global hidden-source conflict absence are not inferred. Alternative hashes identify their original sources; the selected original's bytes are checked, and other originals remain separately inspectable.

GET /v1/claims/{claim_id}/events?before_id=... provides25 currently authorized claim events at a time. Event IDs are exact signed64-bit strings, including values above JavaScript's safe integer range. Every page reloads the claim's current complete source authorization. Unknown or revoked claims/events remain withheld without deletion. Event history is not a global audit-chain attestation.

POST /v1/review/{claim_id} accepts optional expected_context for backward compatibility. The forthcoming UI must send the displayed comparison context and exact claim revision. A changed context rejects before mutation. Decisions retain that context in audit/event details. Every source used by the context hash is retained in the claim/review dependencies, including contest/reject decisions; revoking a comparison alternative consequently withholds derived review state even if primary original custody remains authorized.

This is a snapshot-scoped decision, not a promise that no future or hidden source can conflict.
